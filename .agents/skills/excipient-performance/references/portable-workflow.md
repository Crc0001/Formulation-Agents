# 可移植研究契约 v1

适用：任何能读取文本的模型。完整执行另需原文检索/阅读能力；数值执行需Python或宿主明确注册的同版本计算器。没有某能力时记录缺项，继续可完成的部分。不要求某家模型、搜索引擎、密钥或历史对话。

## 从零开始

接收原方和一个实际变化方案，以及已知物料规格、工艺、目标响应。未知字段保留null。原方不可得时先研究明确的局部规格差异，不声称整方预测。全部方案未变化时报告无比较对象，不开展虚构专项。

先建立一条研究任务对象，保存在文件或宿主阶段记录中：

```json
{
  "schema_version": 1,
  "task_id": "caller-assigned-id",
  "context": {"baseline": null, "adjusted": null, "process": null, "method": null},
  "changes": [],
  "responses": [],
  "search_audit": [],
  "studies": [],
  "mechanism_edges": [],
  "calculations": [],
  "transfer_checks": [],
  "gaps": [],
  "next_actions": []
}
```

这是研究交接格式，不是现有项目API的请求结构；接入时转换，不能把整个对象直接塞入不兼容接口。

## 每阶段留下可接手的内容

1. changes：物料ID、原值/新值、单位、质量基准、牌号、粒径口径、加入阶段、同时变化因素；未知值null。
2. search_audit：真实查询、引擎/渠道、日期、命中URL、全文取得状态、纳入/排除理由、尚未覆盖路径。不能预填“已检索”。从变量检索，而不是只从药名或BCS类别检索。
3. studies：study_family、对照组身份、条件、原始值/单位、表图定位、误差和重复数；每项数值标raw_table、image_estimate或author_fitted_parameter。摘要仅导航。
4. mechanism_edges：输入→输出、具体方程及单位、来源、经验/物理/闭合假设身份、适用范围、参数来源、竞争机制。将方向相反的贡献同时保留；只知道C下降不能忽略φ上升。
5. calculations：模型ID/版本、输入文件、执行命令或真实工具名、输出文件、执行状态、误差定义。读过方程不算执行；可以先算局部量，不必等待整方模型齐全。
6. transfer_checks：逐边列明来源与目标差异，哪些结构可沿用、哪些参数需重估。无依据时目标值null；记录具体原因和下一条检索/测量。

顺序为证据技能→建模技能→验证技能→总体交付；每阶段先保存再继续。后续模型读取文件和未完成项续接，不重复从零开始。宿主提供save_excipient_stage时按其实际签名保存；否则写本地JSON，不假称已归档项目。

## 可执行能力与扩展

已提供：相邻机制技能的powder_yield.py（Python标准库，线性剪切参数重建）；本技能filler_physics.py（显式参数的局部物理计算，依赖见脚本）；paired_case_report.py（报告，不是求解器）。综合速率迁移属于当前项目宿主工具，复制技能不会自动安装该工具。

对于淀粉、MCC、崩解剂、润滑剂等，复用的是检索—参数—试算—验证过程，不是乳糖参数。选择响应后检查已有模型是否适用；不适用则新增有出处的模型实现、明确输入单位/来源/范围、附可独立复算例与失败输入检查，再加入模型目录。不得把所有作用都折算为一个溶出速率乘数。

## 交付和验收

左侧显示来源对照及实测/作者拟合参数/重建的准确身份，右侧显示目标条件预测或具体未定参连接。数值验证、来源校准、独立留出、目标验证分别标记。已有双栏报告器只接收其声明的契约；无法表示作者参数重建时单独输出表格，不将参数伪装为原始实测来通过校验。

最低复用验收：在不提供历史对话、不使用原项目数据库的环境中运行标准例；得到0.37312656/0.52112890 kPa、零变化为零、错误单位/缺来源/区间外输入被拒绝；目标溶出保持null。再给未知规格的新辅料，模型应开展该物料专项检索而非直接套乳糖系数。后者是模型行为评测，数值脚本自测不能替代。
